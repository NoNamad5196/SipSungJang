## 반응형

- 1440×1000: 주요 5화면과 게임 상세/대화상자 검증. 3열 오늘 화면과 캐릭터 카드, 파티 목록 확인.
- 768×1024: 축소 사이드바, 파티 2열 슬롯, 편집 폼 확인. 문서 너비 768px로 수평 넘침 없음.
- 390×844: 오늘/주간/설정/게임 상세/캐릭터 편집/빈 수첩, 고정 하단 내비게이션 확인. 문서 너비 375px(스크롤바 제외), 페이지 수평 넘침 없음.
- 360×800: 캐릭터 목록과 필터 확인. 문서 너비 345px(스크롤바 제외), 페이지 수평 넘침 없음.
- 좁은 화면의 게임 목록은 의도적인 내부 가로 스크롤입니다. 하단 메뉴를 가리던 개발 도구 표시를 상단으로 이동했습니다.

## 실제 브라우저 기능 검증

| 흐름                          | 결과                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------- |
| 게임 생성·이름/상태/목표 수정 | 검증용 모험 생성, 이름 수정, 휴식 전환, 목표 유지                               |
| 퀘스트 생성·수정              | 목표 3회 퀘스트를 생성하고 2/3 진행 저장                                        |
| 완료·취소                     | 체크 후 새로고침 유지, 취소 후 개수/진행도 갱신                                 |
| 부분 진행 다시 시작           | 2/3의 일일·주간 진행을 초기화 가능                                              |
| 캐릭터 생성·수정              | 레벨 50/90, 육성 6/10, 애정캐 우선순위, 메모 저장                               |
| 파티                          | 슬롯 편성/메모 저장, 연속 저장 시 중복 생성 없음, 중복 캐릭터 선택 시 오류 표시 |
| 메모·최근 접속                | 일반 메모와 오늘 접속일 저장                                                    |
| 데이터 유지                   | 새로고침 후 퀘스트·캐릭터·파티·프로필 확인                                      |
| 삭제                          | 캐릭터 삭제 시 슬롯 비움, 파티 삭제, 게임 삭제 후 목록 이동                     |
| 오류                          | 중복 게임 등록과 중복 파티 캐릭터 오류가 한국어로 표시됨                        |
| 빈 상태                       | 새로운 기기 수첩에서 첫 게임 등록 안내 확인                                     |
| 설정                          | 닉네임/일일 안내 옵션 저장, 새로고침 후 유지 및 실제 안내 표시                  |
| 백업 내보내기                 | 다운로드된 JSON 파일 확인(게임 6개·캐릭터 7명인 검증 시점)                      |
| 정렬                          | 게임 순서 이동, 새로고침 후 유지                                                |

검증용 게임/캐릭터/파티는 삭제했으며 예시 프로필 설정은 복원했습니다. 실제 기기 수첩에 테스트 데이터를 추가하지 않았습니다.

`npm test`: 11개 통과. 공통 ID/별칭, V1 ID·메모·완료 상태와 원본 키 보존, CRUD/관계 정리, 정렬 원자성, 중복 게임 방지, 백업 병합/참조 변환, 손상·저장 용량 실패 시 원본 보존, 잘못된 백업 거부, KST 경계 시간, 프로필/예시 분리, 클라우드 복원 ID 및 표시 이름 변경 시 식별자 유지.

`npm run lint`, `npm run typecheck`, `npm run build`가 모두 통과했습니다. 빌드 산출물에는 주요 화면과 `/api/catalog`, 동적 `/games/[id]` 경로가 포함됩니다.

개발 서버 종료 후 `npm run start -- --hostname 127.0.0.1 --port 3100`으로 실제 프로덕션 빌드를 실행했습니다. 완료 체크→새로고침 유지→취소를 확인했고, 새 브라우저 탭에서 오늘/주간/설정 이동과 런처를 확인했습니다. 최종 프로덕션 탭의 콘솔 경고/오류는 0건입니다. 카탈로그 HTTP 요청은 200, 버전 1, 게임 8개/프랜차이즈 6개, 원신 ID `genshin-impact`를 반환했습니다.

## 확인 범위와 후속 검증

- Chrome 확장 프로그램의 로컬 파일 접근 권한 때문에 자동화의 `fileChooser.setFiles`가 거부됐습니다. 다운로드는 확인했으며 **업로드 선택부터 복원까지의 브라우저 왕복은 미검증**입니다. 백업 검증·병합·복원 로직은 자동 테스트로 확인했습니다. 브라우저 확장 권한을 사용자가 설정한 뒤 파일 선택 흐름을 추가 검증할 수 있습니다.
- Google 실제 계정 로그인, Firestore 네트워크 읽기/쓰기, 운영 보안 규칙은 검증하지 않았습니다. 프로덕션 자료에는 접근·변경하지 않았습니다. 배포 전 테스트 계정/에뮬레이터에서 접근 격리와 네트워크 실패 경로를 검증해야 합니다.
- 후순위: 두 서비스 실제 URL/공통 인증 연결, 게임별 자동 갱신/과거 주차, 푸시 알림, 여러 기기 동시 편집 충돌 해결, 미등록 게임 별칭의 카탈로그 편입.
